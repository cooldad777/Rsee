## Content

Seer is the personal operating layer. It is not SEE, R (the public hub). It is not the firm. It is not a vendor chat that remembers you.

**Job:** keep questions durable so they can be asked again, revised, and answered with files — not with a personality.

**What a public reader is allowed to know**

1. Questions are first-class objects. An answer that cannot point at a file is a draft.
2. Local-first: the living store is on the owner’s machines and private git. Public Pages get only what is Settled and public-safe.
3. Depth is private on purpose. Health notes, Monitor weights, mail archaeology, employer craft, and novel catalog do not graduate by default.
4. AI is an instrument on the desk. Anti-Attachment applies here first.
5. Markdown is the portable constitution. Load the smallest true file. Supersede; do not silent-rewrite.

**What Seer is not**

- Not a friend, oracle, or eleven-vendor stack.
- Not GROUNDED (that is a weekly practice with its own door).
- Not Adventure Within (music has its own door).
- Not a forever chat that accumulates attachment in lieu of commits.

If it did not land as a SHA on a repo the owner controls, it did not happen for Seer.

## Systems

Three loops, all local-first. Public surfaces report shape only.

| Loop | Grain | What it writes |
|---|---|---|
| Question | Seed / sapling | Open questions with owner, date, overlap |
| Answer | Response | Stimulus → action → artifact path → status |
| Stamp | Beat | Dated thinking: what / why / moved / still open |

**Minimum viable desk (public shape, no private paths invented)**

- A vault the owner can write (this repo is the rehearsal log).
- A public canon that is read-only until an explicit go (`cooldad777.github.io`).
- A pass log that stamps before → after.
- A garden where every idea has equal edit weight.
- A halt. Cap the session. Do not grow 32 files overnight.

**Routing an open question**

1. Name the overlap (Garden idea, Chronicle beat, Consulting/Install, or none).
2. Run the same three functions the Loop already uses: Content + (Profit if commercial else Systems) + Hybrid.
3. Write the file. Prepend the pass. Commit.
4. Leave at most three still-open items. Batch any ask to Ryan.

**Membrane (locked)**

- Public-safe: no employer names, no Gmail/Drive on this desk.
- Private `see-r-os` may 404. Do not invent it.
- Pages stay read-only unless Ryan types go.
- Safety veto on mail, Drive, Monitor unveil.

Progress a stranger can read: commits on GitHub, idea files that exist, pass numbers that increment, still-open lists that shrink or get named.

## Hybrid

Seer borrows firm discipline without becoming the firm.

| Neighbor | Boundary |
|---|---|
| SEE, R | Public spine. Seer is not the home door. |
| SEER Consulting | Human counsel with analytics inside the work. Seer is the owner’s desk, not a client deliverable. |
| SEER Install | Install a markdown/context layer, train, leave. Seer never “leaves” the owner; Install must. |
| Idea Garden | Nursery. Seer is one sapling in it, not the orchard manager. |
| Seer Chronicle | Dated thinking beats. Sibling grain. Do not dump beats into idea files. |
| Digital Pensieve | Three layers: raw archive, factual timeline, interpretation. Seer must not let interpretation overwrite the archive. |
| Anti-Attachment | Bouncer for this desk. If the model starts sounding like a companion, stop and write a file instead. |
| GROUNDED | Weekly attention practice. Seer does not schedule it, sell it, or tokenize it. |

The hybrid claim: a personal OS is useful only if it stays smaller than the life it serves. Questions compound. Tools do not get a vote.
